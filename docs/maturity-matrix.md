# Maturity Matrix para Engineers

## 🎯 Objetivo

A Maturity Matrix define níveis de expectativa para engineers em diferentes stages da carreira. Ajuda a:

- Set expectations claras
- Avaliar performance objetivamente
- Planear crescimento de carreira
- Calibrar promotions e compensation

## 📊 Níveis de Maturidade

### Nível 1: Junior / Associate Engineer

**Scope:** Individual tasks com supervisão

**Expectativas:**

| Área | Expectativa |
|------|-------------|
| **Technical** | Completa tasks bem definidas; precisa de guidance em design |
| **Delivery** | Entrega com qualidade dentro de timelines razoáveis |
| **Communication** | Comunica progress e blockers; pede help quando necessário |
| **Collaboration** | Participa em team activities; receptive a feedback |
| **Ownership** | Owns assigned tasks; escalating issues appropriately |

**Indicadores de Progresso:**
- ✅ Completa stories sem rework significativo
- ✅ Pede help cedo, não no deadline
- ✅ Aprende com code reviews
- ✅ Começa a entender o sistema como um todo

### Nível 2: Mid-Level Engineer

**Scope:** Features e módulos com autonomia

**Expectativas:**

| Área | Expectativa |
|------|-------------|
| **Technical** | Design e implementa features completas; code quality consistente |
| **Delivery** | Previsível e confiável; gerencia bem o tempo |
| **Communication** | Comunica proativamente; documenta trabalho |
| **Collaboration** | Colabora com peers; dá e recebe feedback construtivo |
| **Ownership** | Owns features end-to-end; pensa em trade-offs |

**Indicadores de Progresso:**
- ✅ Entrega features completas com mínima supervisão
- ✅ Antecipa problemas e comunica cedo
- ✅ Mentor informal de juniors
- ✅ Contribui para melhorias de processo

### Nível 3: Senior Engineer

**Scope:** Sistemas e cross-team initiatives

**Expectativas:**

| Área | Expectativa |
|------|-------------|
| **Technical** | Design de sistemas complexos; best practices e padrões |
| **Delivery** | Entrega valor consistente; gerencia dependências complexas |
| **Communication** | Comunica claramente com stakeholders; influencia technical decisions |
| **Collaboration** | Colabora cross-team; resolve conflitos técnicos |
| **Ownership** | Owns sistemas ou áreas; pensa em longo prazo |

**Indicadores de Progresso:**
- ✅ Lead de iniciativas técnicas significativas
- ✅ Mentor ativo de juniors e mids
- ✅ Influencia direção técnica da equipa
- ✅ Balança trade-offs técnicos e de negócio

### Nível 4: Staff / Principal Engineer

**Scope:** Organização-wide impact

**Expectativas:**

| Área | Expectativa |
|------|-------------|
| **Technical** | Arquitetura de sistemas críticos; define standards organizacionais |
| **Delivery** | Entrega impacto em múltiplas equipas ou organização |
| **Communication** | Comunica visão técnica; alinha stakeholders senior |
| **Collaboration** | Colaboração org-wide; resolve problemas complexos cross-functional |
| **Ownership** | Owns strategic technical initiatives; pensa em escala e longo prazo |

**Indicadores de Progresso:**
- ✅ Impacto além da própria equipa
- ✅ Define direção técnica para a organização
- ✅ Desenvolve outros senior/staff engineers
- ✅ Resolve problemas que bloqueiam a organização

## 🎯 Assessment Guidelines

### Como Avaliar

1. **Coleta dados:**
   - Code reviews e qualidade de código
   - Feedback de peers e stakeholders
   - Delivery track record
   - Self-assessment

2. **Mapeia para expectativas:**
   - Compara com nível atual
   - Identifica gaps e strengths
   - Considera contexto (team, project, tenure)

3. **Discute com engineer:**
   - Partilha assessment
   - Ouve perspectiva deles
   - Acorda em plano de desenvolvimento

### Calibration

Para garantir consistência:

- **Regular calibration sessions** com outros managers
- **Usa exemplos concretos**, não feelings
- **Documenta rationale** para promoções
- **Revisa periodicamente** (quarterly)

## 📈 Progression Framework

### Timeline Típica

| Nível | Tempo Típico | Notas |
|-------|-------------|-------|
| Junior → Mid | 1-2 anos | Depende de baseline e learning curve |
| Mid → Senior | 2-4 anos | Requer demonstração de ownership e liderança |
| Senior → Staff | 3-5+ anos | Requer impacto org-wide consistente |

> ⚠️ **Importante:** Tempo não é o único fator. Foca em **impacto** e **maturidade**, não tenure.

### Critérios de Promoção

**Para cada nível, pergunta:**

1. **Performance:** Está a performar consistentemente no nível atual?
2. **Scope:** Já está a operar no próximo nível?
3. **Sustentabilidade:** Consegue manter este nível de forma consistente?
4. **Impact:** O impacto é visível e reconhecido?

## 🚩 Anti-Patterns

**Evita:**

- ❌ Promover por tenure apenas
- ❌ Ignorar soft skills
- ❌ Assumir que technical excellence = promoção
- ❌ Falta de transparência nos critérios
- ❌ Inconsistência entre equipas
