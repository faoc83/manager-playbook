# Skill Matrix para Engineers

## 🎯 Objetivo

A Skill Matrix mapeia competências técnicas e comportamentais da equipa. Serve para:

- Identificar gaps e strengths da equipa
- Planear hiring e desenvolvimento
- Facilitar mentorship e pairing
- Suportar decisões de staffing

## 📊 Estrutura da Matriz

### Dimensões

Uma skill matrix típica tem:

1. **Skills:** Lista de competências relevantes
2. **Levels:** Escala de proficiência (ex: 1-5)
3. **People:** Team members avaliados
4. **Evidence:** Exemplos concretos para cada avaliação

### Exemplo de Levels

| Level | Descrição | Exemplo |
|-------|-----------|---------|
| **1 - Awareness** | Conhece o conceito, nunca usou | Ouve falar de Kubernetes |
| **2 - Novice** | Usou com guidance significativa | Seguiu tutorial de K8s |
| **3 - Competent** | Usa independentemente em situações normais | Deploy de apps em K8s |
| **4 - Proficient** | Usa em situações complexas, ajuda outros | Debug de issues em K8s |
| **5 - Expert** | Referência, define best practices | Arquiteta sistemas em K8s |

## 🛠️ Skill Categories

### Technical Skills

**Frontend:**
- HTML/CSS
- JavaScript/TypeScript
- React/Vue/Angular
- State management (Redux, etc.)
- Testing (Jest, Cypress)
- Performance optimization
- Accessibility

**Backend:**
- Linguagens (Python, Java, Go, etc.)
- APIs (REST, GraphQL)
- Databases (SQL, NoSQL)
- Caching (Redis, etc.)
- Message queues (Kafka, RabbitMQ)
- Microservices architecture

**DevOps/Platform:**
- CI/CD (GitHub Actions, Jenkins)
- Cloud (AWS, GCP, Azure)
- Containers (Docker, Kubernetes)
- Infrastructure as Code (Terraform)
- Monitoring (Prometheus, Grafana)
- Security best practices

**General:**
- Git e version control
- Code review
- Debugging
- System design
- Testing strategies

### Soft Skills

- Communication (written e verbal)
- Collaboration e teamwork
- Problem solving
- Time management
- Leadership e mentorship
- Adaptability
- Critical thinking
- Empathy e emotional intelligence

## 🎯 Como Usar

### 1. Definir Skills Relevantes

- Adapta à tua stack tecnológica
- Inclui skills atuais e futuras (para hiring/growth)
- Mantém a lista focada (15-25 skills máximo)

### 2. Avaliar Team Members

**Métodos:**
- **Self-assessment:** Engineers avaliam-se
- **Manager assessment:** Tu avalias baseado em observação
- **360° feedback:** Peers também avaliam
- **Evidence-based:** Requer exemplos concretos

**Melhor prática:** Combina self + manager assessment com discussão.

### 3. Analisar Resultados

**Perguntas a fazer:**
- Quais skills têm gaps críticos?
- Quem são os experts em cada área?
- Há single points of failure?
- Que skills precisamos para o futuro?

### 4. Criar Plano de Ação

**Exemplos:**
- Training ou courses para gaps
- Pair programming para knowledge sharing
- Hiring para skills em falta
- Projects stretch para desenvolvimento

## 🔄 Manter Atualizada

**Frequência:**
- Review quarterly (rápido update)
- Deep dive bi-annually

**Quando atualizar:**
- Após projetos significativos
- Quando alguém aprende skill nova
- Antes de planning ou hiring

## 🚩 Anti-Patterns

**Evita:**

- ❌ Usar para comparar ou rankar engineers
- ❌ Avaliar sem evidence concreto
- ❌ Esquecer de atualizar regularmente
- ❌ Focar apenas em technical skills
- ❌ Ignorar contexto (tenure, opportunities)

## 💡 Dicas Práticas

1. **Torna visível:** Partilha com a equipa (transparência)
2. **Foca em growth:** Usa para desenvolvimento, não julgamento
3. **Celebra progress:** Reconhece melhoria de skills
4. **Link a goals:** Conecta a objetivos individuais e de equipa
5. **Sê honesto:** Melhor under-promise que over-promise

## 📊 Visualização

Considera criar visualizações para facilitar análise:

- **Heatmap:** Cores para níveis (verde = expert, vermelho = gap)
- **Radar chart:** Skills por pessoa
- **Bar chart:** Distribuição de levels por skill
